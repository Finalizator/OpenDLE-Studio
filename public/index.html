Model import: Blockbench, glTF and drag & drop
Import glTF 2.0 / GLB, or a Blockbench .bbmodel project straight from Blockbench — cubes, groups, embedded textures and animations are converted on import (animations are baked to glTF clips). glTF needs its .bin and textures selected or imported with their folder. Model folder reads a whole folder, and dropping files or folders anywhere on this panel imports them (models first, then images, then sounds). Blockbench models import at 1/16 scale: the default model scale of 32 map units per glTF unit then matches Minecraft-like proportions. Free-form mesh elements, particle and sound keyframes are reported, not imported. Assign a model in object Properties; configure primitive colliders separately.

Engine tweaks
OpenDLE preview overrides, independent of imported game menus.

        

          
          
Overall sound level scales every sound effect and the soundtrack on top of the imported game's own volume and music volume (0 is silent, 1 is full). It is saved in this browser, so it still applies on your next session, and it overrides the project's saved values when Play level or Play game starts.

          
Space jumps; E uses doors and switches. Enabled by default. Applies to all projects in this browser, including Play level and Play game.

          
Jumping respects walls, ceilings and grounded physics, but can bypass original map puzzles. Disable for classic no-jump movement. The jump input rule remains editable in visual scripts.

          

          
          
Render resolution sets the internal resolution the renderer draws at; the canvas is then scaled to fit its panel. Display size renders at the panel's real pixel size (device pixel ratio capped at 2) and is the sharpest option; the presets pick a vertical resolution and keep the panel's aspect ratio, so a lower one gives a softer classic look with fewer pixels to shade. Render scale multiplies the chosen resolution (0.5–1.5×, so 1.5 supersamples), and the imported game's classic low-detail mode still halves horizontal resolution. Render resolution, field of view, brightness and mute are preview overrides here, not extra entries in the imported game's menus. Fullscreen is available on the editor's preview toolbar.

OpenDLE: Studio
A source-available game engine and visual editor, not a GZDoom port.

        

          
Working in this milestone

          
A Construct-inspired workspace with Properties, Project and Objects bars; shared 2D/3D room, wall, vertex and entity editing; a 3D fly camera and transform handles; undo/redo; JSON projects; sector materials and lighting; object-owned event sheets; WebGPU-preferred rendering with WebGL2 fallback and Rapier 3D physics; Blockbench GLB/glTF meshes, skins and exported animations; local DeepSeek proposals; MCP tools.

          
Visual scripting scope

          
Double-click an object or choose Edit object script in Properties to attach conditions and actions to that instance. HUD elements link to rules through HUD element IDs. Sheets support nested events, AND/OR conditions, NOT, comments and active groups. Global and per-object variables support numbers, text and booleans. Event parameters accept bounded math/text expressions; shader uniforms and effect toggles are visual commands too. Environment includes a portable GLSL effect editor, not unrestricted GLSL or automatic GZDoom shader translation. Browser WebGPU may use Vulkan internally, but native Vulkan is not exposed directly. This is an original editor, not Construct or GDevelop project-format compatibility: families, automatic instance picking, reusable behaviors and node graphs are not implemented.

          
Doom II compatibility: static map and asset preview

          
Import classic little-endian IWAD/PWAD maps with sector geometry, composed wall textures, flats, palette-decoded sprites, sky, weapon overlays and an editable status bar reconstructed from WAD artwork. Digit fonts, face clips, weapon slots, keys and ammo bind to runtime inventory. Imported Engine sheets contain editable inventory, pickup and selection rules. Use Local WAD library to import your Freedoom file from Projects. No commercial game assets are included. Existing imports need reimporting to obtain this HUD; save/export custom edits first.

          
The target is full, one-way GZDoom game import into native, editable OpenDLE content; OpenDLE extensions need not run in GZDoom. Import PK3 / IPK3 opens ZIP resource packages, including standalone games; Local package library discovers unpacked folders and nested packages under Projects. Classic Doom and UDMF geometry import with an optional base IWAD. UDMF source properties are retained as provenance. Binary Hexen maps and PK7 are not supported yet.

          
The WebGL renderer supports floor/ceiling heights, two-sided wall openings, masked midtextures, animated billboard sprites, weapon/impact frames, classic animated surfaces, sector light levels, up to 16 colored point lights and panorama or six-face skies. Nine weapons, visible projectiles, basic enemy chasing/attacks, classic doors/lifts/floor movement, sound playback and inventory/pickups use editable Engine rules. Space/E uses doors and switches. Remaining compatibility gaps include exact weapon/actor state machines, directional sprite rotations, special monster abilities, power-ups, exact face logic, generalized specials, advanced UDMF properties, music, ACS, DECORATE, ZScript and custom HUD/texture definitions. These are in scope but not implemented; geometry import is not full gameplay compatibility.

          
Visual editors, incrementally

          
This foundation covers maps, events, imported images, sector surfaces, material assignments, sky and weapon selection, light settings and a separate HUD designer. HUDs support anchored drag/resize layouts, nine-patch images, web/grid-bitmap fonts, scoped CSS classes, sprite-frame/tween animations, engine bindings and clickable visual scripts. Canva PNG/JPG/WebP exports are flattened images, not editable Canva layers. Full texture painting, world sprite animation authoring and audio editing remain future work. A complete game engine is a multi-milestone project.

          
AI is optional

          
The editor works without a provider account. Set DEEPSEEK_API_KEY on the local server to request tool-driven drafts. Review and explicitly apply each draft. Project content is sent to DeepSeek only when you request it. MCP clients can edit the saved server project directly; reload to see their changes.
